# 球员录入规范

## 目标

后续真实数据录入以球员为主线推进，采用“核心闭环优先”的节奏：每录一个球员，先让球员详情、关联国家、关联俱乐部、个人奖项和核心荣誉形成可查看、可重算、可校验的一条完整链路。

本规范用于约束后续录入顺序、数据归属和验收方式。最终以页面编辑后的数据库内容为准；脚本只用于赛事结果、批量奖项或明确需要可重放的数据。

## 录入原则

- 先录球员，再补关联实体和核心荣誉，不为了一个球员一次性补完整个世界足球历史。
- 球员、国家、俱乐部、奖项基础信息以页面最终编辑结果为准，避免脚本覆盖人工修正。
- 赛事结果仍按赛事归档，不按球员或俱乐部拆文件。比如梅西的欧冠荣誉写进欧冠赛事，阿根廷荣誉写进对应国家队赛事。
- 俱乐部国内荣誉可以使用 patch 式补录，但仍按赛事归档，例如英超荣誉写进英超补录数据。
- 不确定 UID 的俱乐部不自动创建脏数据；除非明确允许，否则先标记待补或对应名次暂空。
- 隐藏俱乐部用于真实存在但暂不进入豪门列表的实体，默认 `exists=true`、`visibleInCatalog=false`。
- 球员基础资料和履历资料分开维护：`编辑资料` 只改 Player 基础字段，`履历管理` 维护经历、个人奖项和关联团队荣誉。
- 球队/国家队荣誉不能只按经历自动归属给球员，必须通过关联荣誉确认后才展示到球员详情。

## 命名口径

后续所有核心实体统一按下面口径维护：

| 字段 | 含义 |
| --- | --- |
| `name` | 中文标准名 |
| `englishName` | 英文标准名 |
| `shortName` | 中文简称，先只入库和详情/编辑页维护，列表/紧凑卡片后续再指定使用点位 |
| `alias` | 多别名、历史名、导入识别名 |

补录和导入时遵循同一原则：

- 以数据库现值为准。
- 脚本和导入只负责补空，不覆盖已经人工维护过的 `englishName` / `shortName`。
- `alias` 继续保留给检索和导入识别，不替代 `englishName` / `shortName`。
- 如果某个实体暂时没有英文名或简称，可以先留空，不强行补一版。

## 页面入口

球员详情页提供两个主要操作：

| 入口 | 用途 | 数据归属 |
| --- | --- | --- |
| 编辑资料 | 维护姓名、生日、国籍、位置、能力、身体数据、代表球队、初始球队、备注等基础资料 | `Player` |
| 履历管理 | 维护俱乐部/国家队经历、个人奖项、确认关联的团队荣誉；经历、奖项和关联荣誉均按单条弹框维护 | `PlayerCareer`、`AwardRecipient`、`PlayerTeamHonor` |

不要在 `编辑资料` 中维护奖项和团队荣誉，避免修改基础字段时误动履历数据。

## 优先级

| 优先级 | 内容 | 要求 |
| --- | --- | --- |
| P0 必填 | 球员基础资料、代表国家、代表球队/主要俱乐部、主要位置、退役/已故状态 | 每个球员必须完成 |
| P1 优先 | 主要个人奖项、世界杯/洲际杯/欧冠/解放者杯/世俱杯等核心荣誉 | 优先补齐，保证详情页有完整主线 |
| P2 后续 | 国内杯赛、小杯赛、完整俱乐部历史荣誉、非核心奖项、低优先级经历细节 | 后续逐步补齐 |

## 标准流程

### 1. 球员基础资料

先录或核对以下字段：

| 类型 | 字段 |
| --- | --- |
| 身份 | UID、中文名、英文名、外链 |
| 生卒 | 生日、卒日、退役 |
| 国家 | 代表国籍、国籍、出生国家、出生城市 |
| 能力 | 代表位置、位置、PA、CA |
| 身体 | 身高、体重、惯用脚、球衣号、肤色、发色、种族 |
| 扩展 | 球员类型、市场价值、数据库来源、担任过职位 |
| 说明 | 数据来源、成就摘要、备注 |

基础资料允许先不追求完美，但 P0 字段不能空到影响列表和详情识别。UID 仍为必填；如果资料源暂时没有 UID，可以填 `-` 占位，后续再补真实 UID。

派生字段口径：

- 足联由代表国籍优先派生；没有代表国籍时再参考代表球队，不在球员基础资料中手动选择。
- 已故状态由过世日期派生；填写过世日期即显示“已故”，未填写则显示“在世”。
- 初始球队使用俱乐部下拉选择，保存结构化 `initialClubId`，同时保留球队名称快照用于兼容旧数据。

球员列表字段与录入口径：

| 列表字段 | 录入口径 |
| --- | --- |
| UID、球员 | 手动录入 UID、中文名、英文名 |
| PA | 手动录入 |
| 荣誉分 | 由球员奖项规则重算写回，不手填 |
| 年代 | 由生日自动派生，不手填 |
| 生卒年龄 | 由生日、卒日、退役/已故状态展示，不手填 |
| 代表位置、位置 | 手动录入，使用位置标签口径 |
| 身高、体重、球衣、肤色、发色、种族、左右脚 | 手动录入或选择基础配置 |
| 足联 | 由代表国籍/国家关联派生，不在球员编辑里手动维护 |
| 代表国籍、国籍、出生城市 | 手动关联国家、国籍列表和城市 |
| 代表球队、初始球队 | 使用俱乐部下拉作为基础资料维护；完整球队经历在履历管理中维护 |
| 类型、市场价值、数据库、担任过职位、成就、备注 | 手动录入 |
| 生涯、生命、状态 | 由退役、已故等字段展示，不单独手填 |

奖项数和顶级奖项数由奖项记录和 AwardRule 重算得到，不作为基础资料手动维护。

### 2. 关联实体预检

录球员前先检查这些实体是否存在：

| 实体 | 处理方式 |
| --- | --- |
| 国家 | 不存在则先创建；历史国家按现有历史国家继承口径处理 |
| 俱乐部 | 不存在但确认真实存在时可创建为隐藏俱乐部 |
| 出生城市 | 不存在时按页面能力新增或暂填文本，后续再规范 |
| 奖项 | 不存在则先创建 Award，再录 AwardEdition 和 AwardRecipient |
| 赛事 | 不存在则先按赛事排序规范创建赛事，再补结果 |

如果俱乐部 UID 不确定，不默认填 `-`。先记录到待补项，等 UID 明确后再创建或补 standings。

### 3. 履历管理：球员经历

球员经历分为国家队经历和俱乐部经历：

- 国家队经历使用 `COUNTRY`，关联对应国家。
- 俱乐部经历使用 `CLUB`，关联对应俱乐部。
- 经历只维护开始年份和结束年份，不维护开始赛季、结束赛季。
- 位置组不手动维护，后续根据具体位置派生。
- 代表俱乐部只允许一个，设置 `isRepresentative=true`。
- 重要经历设置 `showInProfile=true`，低优先级或短期经历可暂不展示。
- 传奇阵容候选可设置 `isLegend=true`，但不要把所有效力经历都标成传奇。
- `sortOrder` 按时间或重要程度排序，保证详情页经历顺序稳定。

初始球队和代表球队都优先关联已有俱乐部；如果俱乐部存在但不进入豪门列表，仍可以作为经历和跳转对象使用。

履历管理页面保留为独立页面，不改为基础资料编辑弹框。页面内经历列表用于浏览和整体保存，新增或编辑单条经历时使用弹框，避免大段表单堆在列表区域。

经历用于说明球员效力范围，也用于后续反查可能遗漏的团队荣誉，但经历本身不代表该球员一定计入该队同年所有荣誉。

### 4. 履历管理：个人奖项

个人奖项按奖项体系维护：

- Award：奖项本体，例如金球奖、世界足球先生、洲际年度最佳球员；赛事内奖项需要绑定对应 Competition。
- AwardEdition：奖项届次，例如 2024 金球奖；赛事内奖项届次需要绑定对应 CompetitionEdition。
- AwardRecipient：获奖球员、排名、名次、备注和外链。
- AwardRule：奖项分规则，缺失时先补规则，再重算奖项分。

奖项分类、分值、顶级奖项数和组合折减口径见 `docs/球员奖项规则方案.md`。

赛事内奖项和年度奖项分开维护：

| 类型 | 录入口径 |
| --- | --- |
| 赛事内奖项 | 先选赛事，再选该赛事下的奖项，再选择对应届次；重算时按奖项基础分叠加赛事完整系数 |
| 年度 / 范围奖项 | 先选范围，例如全球、洲际、国家；再选足联或国家，最后选择奖项和年份 |

个人奖项可以在奖项详情维护，也可以在球员履历管理中维护。球员侧维护时，可以按奖项批量选择多个届次，例如 `1972 第二名、1973 第一名`；保存后底层仍拆成多条 AwardRecipient，不把多个年份合并成一条数据库记录。

录入后执行球员奖项规则重算，核对 `awardCount`、`topAwardCount`、`honorScore` 是否符合预期。

### 5. 履历管理：个人成就

个人成就用于维护少量高含金量、跨时代或终身性质的非竞技届次荣誉，例如“FIFA 二十世纪最佳球员”“劳伦斯终身成就奖”。它和 Award/AwardEdition 不同：不按年度奖项届次建模，也不参与奖项数、顶级奖项数统计。

成就录入口径：

- 一条成就对应一条 `PlayerHonor`，在履历管理的“成就”页签单条新增、编辑、删除。
- 字段只维护年份/赛季、成就名称、分值、外链、排序和备注。
- 每条默认 1 分；如后续出现特殊口径，可以手工调整单条分值。
- 成就分计入球员奖项分，并在荣誉分矩阵中单列展示“成就”。
- 成就允许入库超过 10 条，但计分最多 10 分。超过封顶后的成就仍展示在详情和荣誉清单中，不再继续加分。
- seed 只补首批明确数据和空字段，不覆盖页面后续人工维护的名称、分值、外链、排序或备注。

建议录入：

- FIFA、国际足联金球奖、IOC、IFFHS、Laureus、BBC 等权威机构或主流媒体授予的世纪类、终身成就类、历史地位类荣誉。
- 与球员历史定位高度相关，且能在详情页作为“重要成就”展示的荣誉。

不建议录入或不建议计分：

- 普通名人堂、号码退役、纪念奖、公益身份、形象大使、国家勋章、球场命名等非竞技地位类信息。
- 普通媒体榜单、小范围网站榜单、重复转载榜单。
- 球员作为评委或名单发起方的项目，例如 `FIFA 100` 这类“贝利评别人”的名单。
- 纯纪录类条目，例如最年轻进球、进球总数纪录、唯一三夺世界杯等；这类更适合后续单独做纪录模块。

### 6. 履历管理：关联团队荣誉

关联团队荣誉用于确认“某条国家队或俱乐部赛事结果是否归入该球员履历”。它不修改赛事结果本身，而是把球员与已有 CompetitionStanding 建立确认关系。

关联状态：

| 状态 | 含义 |
| --- | --- |
| 已确认 | 在球员详情团队荣誉中展示 |
| 待确认 | 只在履历管理中保留，不进入正式详情展示 |
| 不计入 | 明确排除，避免后续反查时重复误判 |

来源：

| 来源 | 含义 |
| --- | --- |
| 手动资料 | 资料中明确写出的荣誉 |
| 经历反查 | 根据球员经历和数据库已有赛事结果提示的候选项 |
| 批量导入 | 后续批量资料处理产生 |

录入口径：

- 以资料明确写出的荣誉为主。
- 经历反查只作为“可能遗漏”提醒，不自动计入。
- 只有数据库中已存在的赛事结果才能直接关联；缺失赛事、届次或名次时，先去赛事管理补录。
- 如果资料只列冠军，系统反查出的亚军、季军、殿军需要人工确认后再计入。

只补该球员直接相关的核心荣誉，不要求一次性补齐所有历史。

国家队优先：

- 世界杯
- 欧洲杯、美洲杯、亚洲杯、非洲杯、金杯、大洋洲杯
- 奥运男足、联合会杯等已纳入规则的核心赛事

俱乐部优先：

- 世俱杯、国际足联洲际杯、欧洲/南美洲杯
- 欧冠、南美解放者杯、亚冠等洲际顶级赛事
- 该球员生涯最关键的国内联赛和主要杯赛

赛事结果录入后执行荣誉规则重算，核对国家和俱乐部的荣誉统计与分数；球员详情中的团队荣誉展示以 `PlayerTeamHonor` 的已确认记录为准。

### 7. 核对清单

核对清单用于后续阶段把“资料荣誉”和“经历反查结果”合并展示：

- 资料荣誉：用户明确提供的球队/国家队荣誉。
- 数据库可能遗漏：根据球员经历反查出的已有赛事结果。
- 已匹配：资料荣誉能在数据库找到对应 CompetitionStanding。
- 待补录：赛事、届次或名次尚未录入。
- 待确认：数据库反查到但资料没有明确写出的荣誉。
- 不计入：确认不属于该球员履历的荣誉。

球员荣誉核对必须先建临时清单，再入库。临时清单用于整理该球员重要奖杯、个人奖项和个人成就，不作为长期项目文档；录入、重算和页面核验全部完成后删除。

临时清单约定：

- 文件名建议使用 `docs/{球员名}奖杯奖项成就临时清单.md`，例如 `docs/贝利奖杯奖项成就临时清单.md`。
- 清单内容至少分为 `奖杯 / 关联团队荣誉`、`个人奖项`、`个人成就`、`待确认 / 不计入`。
- 每条记录都要保留录入状态，例如 `待确认`、`可录入`、`已录入`、`不计入`。
- 资料源和系统匹配结果要分开写：资料源说明“球员资料里有什么”，系统匹配说明“数据库里是否已有对应赛事、届次、名次或奖项”。
- 入库前优先匹配系统已有 `CompetitionStanding`、`Award`、`AwardEdition`；匹配不上先列缺口，不硬造赛事、届次、奖项或俱乐部。
- 录入完成后执行重算和页面抽查，再删除临时清单，避免临时资料长期混在正式文档里。

关联团队荣誉确认口径：

- 球队有荣誉不等于球员一定有这条可关联荣誉。
- 只能把已经确认属于该球员履历的赛事结果关联到球员，例如确认球员在该赛季效力该队、进入该赛事名单、参加关键阶段或资料源明确把该荣誉列入球员个人履历。
- 仅凭球员经历时间覆盖球队夺冠年份，不足以直接录入；遇到受伤、离队、未报名、未出场或资料冲突时，先标为 `待确认` 或 `不计入`。
- 如果俱乐部或国家队官方资料把荣誉列入球员履历，但比赛名单显示球员未参与，应在临时清单里备注口径差异，默认先不计入，等用户确认后再处理。
- 已确认的团队荣誉通过 `PlayerTeamHonor` 关联已有 `CompetitionStanding`，不改写赛事结果本身。

### 8. 巨星荣誉清单展示口径

巨星荣誉页的“荣誉清单”只做展示文本压缩，不影响底层 AwardRecipient、PlayerTeamHonor、赛事结果、奖项得分或团队荣誉分。

展示规则：

- 赛事和奖项名称优先使用 `shortName`，没有简称时回退 `name`。
- 列名已经表达语境时，单元格内去掉重复前缀。例如世界杯奖杯列中 `1958、1962、1970 世界杯` 展示为 `1958、1962、1970`；世界杯奖项列中 `1970 世界杯金球奖` 展示为 `1970 金球奖`。
- 冠军、第一名、获奖、入选等默认名次不展示；亚军、季军、第二名、第三名等非第一名仍展示。
- `国际足联世界杯金球奖` 特殊处理：`第一名 / 第二名 / 第三名` 在展示层分别显示为 `金球奖 / 银球奖 / 铜球奖`，荣誉清单中直接作为奖项标题展示，不再额外拼接“第二名”等名次。该规则只针对 `FIFA_WORLD_CUP_GOLDEN_BALL`。
- 同一奖项多个年份优先按奖项合并，并且只有大于 1 次时才显示次数。例如 `1962 丰田杯最佳射手；1963 丰田杯最佳射手` 展示为 `1962、1963 2次丰田杯最佳射手`。
- 剩余没有形成多年份合并的单年奖项，再按同一年合并。例如 `1959 美洲杯最佳球员；1959 美洲杯最佳射手` 展示为 `1959 美洲杯最佳球员、最佳射手`。
- 如果同一年合并和同奖项合并同时可用，优先同奖项合并。例如 `1959 美洲杯最佳球员；1959 美洲杯最佳射手；1961 美洲杯最佳球员` 展示为 `1959、1961 2次美洲杯最佳球员，1959 美洲杯最佳射手`。
- 球队主体仍用于奖杯类荣誉，避免球员多队经历下无法识别荣誉归属。例如俱乐部奖杯可展示为 `1962、1963 桑托斯2次解放者杯`。
- 国内联赛奖杯存在展示压缩：如果同一球员已经有 2 种以上国内一级联赛奖杯，荣誉清单中不再展示国内二级/以下联赛奖杯；绑定到这些低级国内联赛的个人奖项也同步不展示。该规则只影响清单文本，不影响底层赛事结果、球员关联荣誉或计分。
- 成就列展示所有结构化个人成就，按年份正序、排序值和名称排序，不套用奖项/奖杯压缩隐藏规则。

特殊奖项名次转换优先写在后端清单生成注释和前端奖项展示工具中，保持底层 `rank / placement` 原始数据不变。

### 9. 页面核验

每个球员录完后固定检查：

- 球员列表：姓名、代表国籍、代表球队、位置、PA、状态显示正确。
- 球员详情：基础资料、经历、奖项、生涯摘要无明显缺失或重复。
- 履历管理：经历、个人奖项、关联荣誉状态正确。
- 国家详情：代表球员、阵容、国家荣誉统计正常。
- 俱乐部详情：代表球员、阵容、俱乐部荣誉统计正常。
- 巨星荣誉：奖项记录能展示，数量和顶级奖项数正确。
- 国家荣誉和豪门荣誉：新增赛事结果能参与统计，隐藏俱乐部有荣誉时也能出现在荣誉统计中。

## 样板球员建议

正式大批量录入前，先用 3-5 个样板球员跑完整流程：

| 类型 | 建议样本 | 覆盖点 |
| --- | --- | --- |
| 现役多俱乐部 | 梅西、C 罗 | 多俱乐部经历、国家队荣誉、个人奖项 |
| 退役巨星 | 齐达内、罗纳尔多 | 退役状态、国家队和俱乐部核心荣誉 |
| 已故传奇 | 贝利、马拉多纳 | 已故状态、历史数据、国家队核心荣誉 |
| 欧洲传奇 | 克鲁伊夫、贝肯鲍尔 | 欧冠、欧洲杯/世界杯、历史俱乐部 |

样板球员跑通后，再按相同清单批量扩展。

## 注意事项

- 不要因为录一个球员，把所有相关俱乐部的全部国内荣誉都强制补齐。
- 不要把球员相关荣誉拆成球员文件；赛事结果始终按赛事归档。
- 不要让 seed 覆盖页面手动修正过的名称、别名、外链、UID 等基础信息。
- 不确定来源时宁可留待补项，不要为了数量完整写入可疑数据。
- 每次补完赛事结果或奖项后，要记得重算对应规则，否则页面统计可能不会立刻变化。
